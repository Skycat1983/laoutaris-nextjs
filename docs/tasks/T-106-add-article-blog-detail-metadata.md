# T-106 Add Article And Blog Detail Metadata

Status: Completed

Workstream:
[Frontend Routes And Components](../workstreams/frontend-routes-and-components.md),
[Deployment, Security, And Observability](../workstreams/deployment-security-and-observability.md),
[Testing And Quality](../workstreams/testing-and-quality.md)

## Goal

Add route-specific metadata, canonical/social preview data, and minimal
structured data for public article and blog detail pages without changing page
layout, route cache policy, content fetching contracts, or commerce/legal
claims.

## Context

- F-085/R-030 remain partially mitigated after T-103.
- T-103 replaced scaffolded root metadata and added baseline `robots.ts` and
  `sitemap.ts`, but route-specific detail metadata and JSON-LD remain open.
- `/biography/[slug]` renders public article detail content through
  `ArticleLoader`.
- `/blog/[slug]` renders public blog detail content through `BlogDetailLoader`
  and can show comments via query string.
- Product/artwork detail metadata, breadcrumb/product/artwork structured data,
  image tuning, and route cache/ISR policy should stay separate.

## Scope

- In scope:
  - Add `generateMetadata()` for `/biography/[slug]` and `/blog/[slug]` using
    existing server data services rather than same-app HTTP.
  - Include stable titles, descriptions, canonical URLs, Open Graph metadata,
    and Twitter card metadata derived from existing public content fields.
  - Add minimal page-rendered JSON-LD for article/blog detail pages using
    conservative `Article`/`BlogPosting` data that does not invent author,
    publisher, policy, sale, or commerce claims.
  - Reuse the existing public site URL helper from T-103.
  - Preserve current `notFound`/error behavior and avoid changing visible page
    layout or comment-query behavior.
  - Add focused tests for metadata construction, canonical URLs, scaffold-text
    absence, and structured-data output/source invariants.
  - Update this task brief and relevant workstreams after completion.
- Out of scope:
  - Artwork, collection-artwork, and Shopify product detail metadata.
  - Product, offer, artwork, breadcrumb, or collection JSON-LD.
  - Sitemap expansion, route-local cache/ISR decisions, or dynamic/static route
    behavior changes.
  - Privacy/terms/cookie policy pages, comment policy notices, checkout/cart,
    shipping/refund/payment claims, or commerce assurance copy.
  - Visual redesign of article or blog pages.

## Acceptance Criteria

- Biography article detail pages expose route-specific title, description,
  canonical URL, Open Graph, and Twitter metadata from article data.
- Blog detail pages expose route-specific title, description, canonical URL,
  Open Graph, and Twitter metadata from blog data.
- Article/blog detail pages include conservative JSON-LD built from existing
  public data only.
- Missing content keeps existing missing/error behavior and does not emit
  misleading metadata.
- Focused tests cover the changed metadata and structured-data contract.
