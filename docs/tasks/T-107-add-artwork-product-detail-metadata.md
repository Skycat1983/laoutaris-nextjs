# T-107 Add Artwork And Product Detail Metadata

Status: Planned

Workstream:
[Frontend Routes And Components](../workstreams/frontend-routes-and-components.md),
[Shopify Commerce](../workstreams/shopify-commerce.md),
[Deployment, Security, And Observability](../workstreams/deployment-security-and-observability.md),
[Testing And Quality](../workstreams/testing-and-quality.md)

## Goal

Add route-specific metadata, canonical/social preview data, and conservative
structured data for public artwork and Shopify product detail pages without
changing visible page layout, route cache policy, saved-item behavior, product
enquiry handoff, or commerce/legal claims.

## Context

- F-085/R-030 remain partially mitigated after T-103 and T-106.
- T-103 added root archive metadata plus baseline `robots.ts` and `sitemap.ts`.
- T-106 added route-specific metadata and conservative JSON-LD for public
  biography article and blog detail pages.
- `/artwork/[artworkId]` renders standalone public artwork detail through
  `ArtworkLoader` and `getArtworkById`.
- `/collections/[slug]/[artworkId]` renders collection-scoped artwork detail
  through `CollectionArtworkLoader` and `getCollectionArtwork`.
- `/shop/products/[productHandle]` renders Shopify product detail through
  `getProductByHandle` and may include linked artwork context.
- T-008/T-100 keep first-release product actions enquiry-based. This task must
  not add checkout, cart, offer, shipping, refund, guarantee, or payment claims.

## Scope

- In scope:
  - Add `generateMetadata()` for `/artwork/[artworkId]`,
    `/collections/[slug]/[artworkId]`, and
    `/shop/products/[productHandle]` using existing server data services rather
    than same-app HTTP.
  - Include stable titles, descriptions, canonical URLs, Open Graph metadata,
    and Twitter card metadata from existing public artwork/product fields.
  - Add conservative page-rendered JSON-LD for artwork and product detail pages
    using existing public data only.
  - Keep product JSON-LD limited to product identity and descriptive fields
    unless sale/offer policy is explicitly approved elsewhere.
  - Reuse existing public site URL and metadata helper patterns from T-103 and
    T-106 where practical.
  - Preserve current invalid artwork ID handling, `notFound()` behavior,
    linked-artwork behavior, saved-item forms, product enquiry link behavior,
    and visible page layout.
  - Add focused tests for metadata construction, canonical URLs, missing/
    unavailable noindex metadata, conservative structured-data output, and
    absence of same-app HTTP or commerce/legal claims.
  - Update this task brief and relevant workstreams after completion.
- Out of scope:
  - Article/blog metadata already handled by T-106.
  - Rich breadcrumb/collection-list structured data beyond minimal detail-page
    JSON-LD.
  - Sitemap expansion, route-local cache/ISR decisions, or dynamic/static route
    behavior changes.
  - Shopify checkout/cart, variant selection, sale terms, shipping/refund/
    payment policy, guarantee copy, or offer/availability claims in JSON-LD.
  - Artwork-to-shop SSR discovery, image sizing/preload tuning, or landmark/
    heading cleanup.

## Acceptance Criteria

- Standalone artwork detail pages expose route-specific title, description,
  canonical URL, Open Graph, Twitter metadata, and conservative artwork JSON-LD.
- Collection-scoped artwork detail pages expose collection-aware canonical
  metadata and conservative artwork JSON-LD without changing loader behavior.
- Shopify product detail pages expose route-specific product metadata and
  conservative product JSON-LD without checkout, offer, sale, shipping, refund,
  payment, or guarantee claims.
- Missing or unavailable content returns noindex metadata and does not emit
  misleading structured data.
- Focused tests cover the changed metadata and structured-data contracts.
